Module 4: Data Cleansing Using Power Query

Keep this page as a desk reference after the session. It summarises what was covered, what to say to reinforce the learning with your team, and what to practise next.

Day 1 · 1:50 PM 75 Minutes Facilitated Demo Excel + Power Query
What This Module Covered
The core argument

Raw data — as it typically arrives from core banking systems, CRM exports, or manual spreadsheets — is almost never ready for analysis. It contains structural problems and quality defects that produce wrong answers silently, with no error message.

Power Query is the tool that bridges the gap between raw data and reliable analysis. It transforms, cleans, and reshapes data through a recorded, repeatable sequence of steps — so the process is auditable and can be re-run every time new data arrives.

The three-tier model

Raw worksheet range — capped at ~1 million rows, fragile cell references, not suitable as a Power Query source.

Excel Table (Ctrl+T) — same row limit, but stable named reference, auto-expanding formulas. Correct source for Power Query.

Power Query + Data Model — ~2 billion rows, compressed storage, no formula overhead in the grid. Calculations run in the DAX/M engine. The right architecture for any data refreshed regularly or exceeding 100k rows.

Data Quality Issues: What Was Wrong and Why It Matters
Issue Severity What goes wrong in analysis How Power Query fixes it
Dates stored as text Structural Time intelligence completely fails. Year, month, quarter slicers return blank. Any date-based KPI is broken. Change Data Type → Date on the Order Date column after the unpivot.
Merged cells in headers Structural Power Query cannot read multi-row merged headers as a table. The query fails or produces wrong column names. Remove Top Rows to delete the merged header rows; Use First Row as Headers to promote the correct row.
Pivot-style layout Structural Ship Mode and Segment do not exist as columns. PivotTable cannot group, filter, or aggregate by either attribute. Unpivot Other Columns converts wide columns into rows, creating Attribute and Value fields.
Duplicate row Wrong numbers One transaction counted twice. Revenue figures overstated. No indicator in Excel — the error is invisible. Remove Duplicates (or identify and remove manually). Verify row counts before and after.
Number with leading space ("  605.47") Wrong numbers Treated as text. SUM ignores it. Sales understated by exactly that amount — again, silently. Transform → Trim removes leading and trailing spaces. Then Change Data Type → Decimal Number.
Number stored as text with comma ("1,044.44") Wrong numbers Same outcome. The thousands separator prevents type conversion. SUM returns zero for that cell. Replace Values: replace "," with "" (empty). Then Change Data Type → Decimal Number.
Blank row Wrong numbers Row counts overstated. COUNTROWS-based measures give the wrong denominator. Averages are off. Home → Remove Rows → Remove Blank Rows.
"N/A" as text instead of blank Subtle failure Creates an extra row in the output after unpivot. Type conversion produces an Error. Row appears in PivotTable with no value. Replace Values: replace "N/A" with blank before changing the data type. Then Remove Errors.
The 14-Step Walkthrough at a Glance
  1. 1ExcelFlash Fill — populate Ship Mode labels explicitly across all 12 columns in row 1.
  2. 2ExcelEnter the formula =B1&"|"&B2 in cell B3 to create a combined Ship Mode | Segment label.
  3. 3ExcelFlash Fill to copy the combined label across all 12 columns (B3:M3).
  4. 4ExcelCtrl+A to select the full data range.
  5. 5ExcelCtrl+T to convert to an Excel Table. Uncheck "My table has headers." Rename the table Orders_Raw.
  6. 6ExcelData tab → From Table/Range — launches Power Query Editor.
  7. 7Power QueryOrient to the interface: Queries Pane (left), Data Preview (centre), Applied Steps (right), Home/Transform/Add Column ribbons (top).
  8. 8Power QueryHome → Remove Rows → Remove Top Rows → 2. Removes the old Ship Mode and Segment header rows.
  9. 9Power QueryHome → Use First Row as Headers. Promotes the combined label row as column names.
  10. 10Power QuerySelect Order Date column → Right-click → Unpivot Other Columns. Converts 12 columns into 3 rows (Date, Attribute, Value).
  11. 11Power QueryAdd Column → Extract → Text Before Delimiter → | — extracts Ship Mode. Rename column "Ship Mode".
  12. 12Power QueryAdd Column → Extract → Text After Delimiter → | — extracts Segment. Rename column "Segment".
  13. 13Power QueryRemove Attribute column. Reorder: Order Date · Ship Mode · Segment · Value. Rename "Value" to "Sales". Fix data types (Date, Decimal). Handle errors. Home → Close & Load.
  14. 14PivotTableInsert → PivotTable from clean table. ROWS: Ship Mode · COLUMNS: Segment · VALUES: Sum of Sales. Sort largest to smallest to surface top revenue combinations.
What to Say to Reinforce the Learning
The central message — use this framing
"Every number in a report or dashboard is only as trustworthy as the data behind it. Power Query is not about technology — it is about ensuring that the analysis your team produces can be defended."
Useful when participants return to their desks and colleagues ask what the session was about.
When someone asks: "We already have a data team — why do I need to know this?"

Say: "You do not need to run these steps yourself every day. But you need to understand what clean data looks like and what bad data costs — because when someone hands you a report and the numbers seem off, you now know the questions to ask. Was the source data a flat table or a pivot export? Were the dates typed or formula-driven? Were there blanks? That is a different conversation than 'the numbers look wrong.'"

When someone says: "Our data comes from the core system — it should already be clean."

Say: "Core banking systems are designed to record transactions accurately. They are not designed to produce flat, analysis-ready tables. The export format — whether it is a pivot report, a multi-level header file, or a CSV with merged rows — is almost always structured for human reading, not machine analysis. That gap is exactly what Power Query closes."

When someone says: "I just use formulas in Excel — that works fine for me."

Say: "Formulas work until the data structure changes — a new column, a shifted row, a merged header — and suddenly your VLOOKUP returns nothing and you do not know why. Power Query connects to the table by name, not by cell address. When new data arrives, you refresh and the same steps run. You spend zero time re-doing manual fixes."

To connect this to Modules 4B, 4C, and 4D

Say: "Everything we do in the next three modules — the formulas, the PivotTables, the Power BI visuals — is built on the clean table we just produced. If that foundation is wrong, everything sitting on top of it is wrong too. This is why we cleaned first."

Discussion Prompts to Use With Your Team

Use these in team meetings, huddles, or one-on-ones in the week after the programme. Each prompt is designed to surface data quality awareness without requiring any tool knowledge.

"Think of a report our team uses regularly. If someone told you one row was duplicated, how would you find it?"
Surfaces awareness of duplicate risk and the absence of validation steps in typical reporting workflows.
"When did you last question whether the data source for a decision was actually clean?"
Opens a conversation about where data quality is assumed rather than verified.
"If the monthly sales report had a number that was off by 10%, would we catch it before it reached the committee?"
Tests whether any validation or reconciliation step currently exists in the reporting chain.
"Which of our regular data exports come to us as pivot-style reports rather than flat tables?"
Practical inventory of where Power Query would add the most immediate value.
"How long does it currently take to prepare data before analysis can start? What would half that time be worth?"
Frames Power Query as a capacity and efficiency investment, not just a technical skill.
"If a regulator asked us to show our working on a data-driven decision, could we?"
Connects data quality and auditability to compliance — highly relevant for banking participants.
Key Concepts to Carry Forward
Applied Steps = the audit trail

Every transformation in Power Query is recorded as a named step. That list IS the documentation. Anyone can open the query and read exactly what was done to the data and in what order. This is the answer to "how did you get this number?"

Unpivot is the most important command

Most raw data arrives in pivot format — values spread across many columns. Unpivot Other Columns converts this into a flat table in one click. Without it, attributes like Ship Mode and Segment cannot be used as filters or groupings in any analysis tool.

Silent errors are the most dangerous

A text-formatted number does not produce an error — it just gets excluded from SUM. A duplicate row does not trigger a warning — it just inflates the total. The analysis runs, a number appears, and no one knows it is wrong. Data quality checks exist precisely because the errors do not announce themselves.

Clean data has three properties

It is flat — one row per observation, one column per attribute. It has correct types — dates are dates, numbers are numbers, not text. And it is free of structural noise — no merged headers, blank rows, or duplicates.

Refresh, not redo

Once a Power Query is built, it never needs to be rebuilt. When new data arrives next month, open the workbook and click Refresh. The same steps run automatically. This is the compounding return on the time invested in building the query correctly once.

The delimiter technique

When multiple attributes need to travel as one column (as in the Ship Mode | Segment label), choose a delimiter that cannot appear in the data — a pipe character is ideal. This allows clean splitting later without ambiguity. A simple pattern with broad applicability in data preparation work.

What to Practise Before the Next Session
Suggested practice tasks
  • Open the CLEAN_Orders file distributed at the end of Day 1 and inspect the Applied Steps list — read each step and match it to the issue it fixed.
  • Find one export or report from your own work that has at least two of the data quality issues from this module. Note which issues and which Power Query steps would address them.
  • Try converting a range in any Excel file to a Table (Ctrl+T). Observe how the column references change in formulas.
  • In Power Query, try changing a column's data type and then deleting that step from Applied Steps — observe how the data reverts.
  • Build the PivotTable from Step 14 on the CLEAN_Orders data and add a slicer for Order Date. Notice that the date slicer works only because Order Date was correctly typed.
Questions to bring to Module 4B
  • What data sources in your organisation would benefit most from a Power Query pipeline?
  • Who currently owns the data preparation step in your team's reporting cycle? Is that process documented?
  • How would you explain the difference between a flat table and a pivot table to a colleague who has never used either?
  • If the Sales column had contained five different currency formats, how would you approach standardising them in Power Query?
  • What is the risk of loading a query directly to the data model rather than to a worksheet? When would you choose each?
The one thing to remember from this module

A report is only as trustworthy as the data it was built on. Power Query makes the preparation step transparent, repeatable, and auditable — turning a recurring manual task into a one-time investment. Clean first. Analyse second. Every time.
